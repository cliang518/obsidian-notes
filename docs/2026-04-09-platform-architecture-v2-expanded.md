# 2026-04-09 弱电综合运维平台 V2 扩展架构

## 1. 新平台正式定位

V2 不再只是“视频维护系统”，而是三层一体的平台：

- 主平台：统一资产、拓扑、告警、视频、工单、巡检
- 存储资源层：文件、图片、视频缓存、文档、对象存储
- Agent/模型层：MCP、智能体接口、LLM Provider、学习引擎

## 2. 核心分层

### 2.1 事实接入层

当前已纳入或已规划的事实源：

- TG/COS 网络与终端平台 `10.0.68.250`
- JVSS 视频平台 `10.0.59.200`
- JVSS 流媒体子平台 `10.0.59.205`
- 海康新 NVR
- 海康老 NVR
- 海康解码器
- 网关
- 交换机
- 摄像头直连信息
- 后续风控/电控平台

原则：

- 第三方平台当前只读
- V2 先吸收事实，再逐步替代
- 平台源优先于人工补录

### 2.2 统一资产层

统一资产层承载：

- 平台
- 网关
- 交换机
- 端口
- NVR
- 解码器
- 摄像头
- 通道
- 区域
- 链路

关键目标：

- 不再多套 ID 并存
- 不再把平台、设备、通道、区域拆散管理
- 支持后续移动端、Agent、报表、知识检索复用同一事实源

### 2.3 业务工作台层

V2 当前和后续工作台：

- 总览中心
- 运行中心
- 资产中心
- 告警中心
- 拓扑中心
- 视频中心
- 接入中心
- 智能接口
- 移动工作台
- 存储资源
- 学习中心

### 2.4 存储资源层

V2 不把存储写死在项目目录。

统一抽象为 `Storage Provider`，支持：

- 本地磁盘
- S3 兼容对象存储
- WebDAV
- 海康存储/录像回放入口
- 后续独立存储服务器

推荐组合：

- SeaweedFS：对象存储与视频缓存
- Nextcloud：统一文件入口和 WebDAV
- Paperless-ngx：文档归档
- Immich：移动端照片、视频资料

### 2.5 Agent / MCP / LLM 层

V2 从架构上预留两类能力：

- 对外：把 V2 暴露给智能体
- 对内：让平台调用模型和外部 MCP

对外能力：

- REST API
- MCP Gateway

对内能力：

- LLM Provider Layer
- MCP Client Gateway

## 3. 移动端策略

移动端不能只靠 PC 响应式。

正式策略：

- PC：完整平台工作台
- Mobile：专用工作流

移动端重点场景：

- 告警确认
- 工单处理
- 巡检执行
- 现场拍照上传
- 设备定位
- 区域快速查询

后续支持：

- 企业微信
- 飞书
- 微信

## 4. 学习引擎策略

V2 的学习功能采用“人工确认式学习”，不做失控自优化。

阶段策略：

### 阶段 1

- 识别模式
- 生成建议
- 记录经验

### 阶段 2

- 学习阈值建议
- 学习根因建议
- 学习高发区域和疑难设备画像

### 阶段 3

- 在人工确认后写回平台规则

学习来源：

- 告警历史
- 工单结果
- 拓扑快照
- 第三方平台同步
- 人工备注

## 5. 第三方平台退出路线

退出顺序不变：

1. 先替代 `10.0.59.205`
2. 再替代 `10.0.59.200`
3. 最后替代 `10.0.68.250`

原因：

- `205` 更偏流媒体子平台
- `200` 更偏视频台账与报警点
- `250` 掌握最难替代的网络关系和端口归属

## 6. 明日继续接入的重点

- 风控/电控平台只读深挖
- 与现有区域、交换机、控制器、告警线索对齐
- 纳入统一资产模型
