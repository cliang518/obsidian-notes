# 开发主机网络基线

更新时间：2026-04-12

## 当前结论

开发主机同时承担开发、部署、内网数据采集与公网访问入口，因此不能只看 Windows 是否配置了某个 IP 段，还必须区分：

- 资料库事实：系统或历史采集数据中记录过该 IP、交换机、摄像头或拓扑关系。
- 本机路由覆盖：Windows 路由表认为某个网段可以从本机发出。
- 实际链路可达：本机当前能 ARP、Ping 或 TCP 连接到目标设备。

本次排查确认：`10.0.68.x` 在资料库里确实是交换机/管理设备密集网段，但当前开发主机实测并不是整个 68 段都可达。

## 推荐 IP 配置原则

本项目现场不是单纯的三层路由网络，很多摄像头、交换机、平台或控制设备可能只配置了 `/24` 掩码，甚至没有可用网关。因此开发主机/部署主机必须在每个需要直达的 `/24` 网段里配置一个同网段本地 IP。

不要依赖一个 `10.0.x.x/16` 或一个跨段 `/22` 来“覆盖全部 10.0 网段”。本机能发出不代表对端能回包。

保留公网/办公访问：

- `172.16.16.233/24`
- 默认网关：`172.16.16.1`

富成视频主线：

- `10.0.56.x/24`
- `10.0.57.x/24`
- `10.0.58.111/24`
- `10.0.59.x/24`

交换机/平台/风控电控预留：

- `10.0.68.197/24`
- `10.0.69.x/24`
- `10.0.70.x/24`
- `10.0.71.x/24`

250 平台资料中还出现过少量相邻或控制网段，如需要全量直达，应补充：

- `10.0.60.x/24`
- `10.0.62.x/24`
- `10.0.63.x/24`
- `10.0.64.x/24`
- `10.0.65.x/24`
- `10.0.66.x/24`
- `10.0.67.x/24`

海康/录像机相关网段：

- `192.168.1.x/24`
- `192.168.5.x/24`
- `192.168.6.x/24`
- `192.168.8.x/24`
- `192.168.119.x/24`

不要把 `10.0.58.111` 和 `10.0.68.197` 都配置成 `/16`。这样会让 Windows 把整个 `10.0.0.0/16` 合并成一条大路由，访问其他 `/24` 时可能错误使用非同段源地址，导致对端设备无法回包。

## 本次实测

修正前：

- `10.0.58.111/16`
- `10.0.68.197/16`
- `10.0.59.200`、`10.0.59.205` 可达。
- `10.0.68.250` 在 ARP 中可见，但 Ping 不稳定；大部分 68 交换机样本不可达。

第一次修正后曾临时使用 `/22`：

- `10.0.58.111/22`
- `10.0.68.197/22`
- `10.0.59.200`、`10.0.59.205` 继续可达。
- `10.0.68.250` 使用 `10.0.68.197` 作源地址可 Ping，可访问 `80/443/23/22`。
- `10.0.68.53` 可访问 `443/23`。
- `10.0.68.12`、`10.0.68.64`、`10.0.68.254` 当前不可达。

后续正式基线应继续细化为每个关键 `/24` 一个部署主机本地 IP，而不是使用 `/22`。

当前 68 段 TCP 扫描结果：

| IP | 开放端口 |
| --- | --- |
| `10.0.68.53` | `443,23` |
| `10.0.68.197` | `22` |
| `10.0.68.250` | `80,443,23,22` |

## 后续系统规则

系统后续做 IP 检索、拓扑归属、交换机补采时必须遵守：

- 不再把“资料库里有 68 段设备”等同于“当前本机可访问 68 段设备”。
- 不再把“Windows 路由表覆盖某网段”等同于“实际链路可达”。
- 不再把 `/16` 或 `/22` 当作跨网段直达的替代方案。
- 68 段交换机清单必须同时显示“资料库记录状态”和“实时可达状态”。
- 对不可达交换机，不能直接判定为设备不存在，应标记为“管理链路不可达/待现场网络确认”。
- 访问异常优先检查：开发主机是否配置了目标 `/24` 同网段 IP、源地址是否正确、所在交换机端口 VLAN、目标交换机管理 VLAN、是否只允许特定源 IP 管理。
