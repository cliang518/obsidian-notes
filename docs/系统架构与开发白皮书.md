# 永嘉集团弱电运维平台 V2 系统架构与开发白皮书

版本：2026-05-06  
项目根目录：`E:/cctv-maintenance/platform_v2`  
适用范围：前端、后端、资产中心、拓扑编辑器、交换机探针与大数据清洗链路

## 1. 系统定位

弱电运维管理系统 V2 是围绕“资产台账、CAD 物理点位、交换机逻辑级联、视频取流诊断、现场核实闭环”构建的综合运维平台。当前主线目标是把资产中心与拓扑中心打通，使现场人员在拓扑编辑器中的拖拽、连线、备注和核实状态，能够持久化到后端数据库，并同步影响资产中心的设备状态与备注。

当前拓扑模块已经正式接入主路由：

| 路由 | 组件 | 说明 |
| --- | --- | --- |
| `/topology` | `TopologyEditorView` | 正式拓扑归属入口，指向新版 G6 拓扑编辑器 |
| `/topology-editor` | `TopologyEditorView` | 隐藏兼容入口，保留调试与旧链接访问 |

## 3. 核心技术栈与规范

### 3.1 Frontend

| 类别 | 技术 | 当前约定 |
| --- | --- | --- |
| 框架 | Vue 3 | 使用单文件组件与组合式 API |
| 构建 | Vite 5 | `npm run dev`、`npm run build`、`npm run preview` |
| UI | Element Plus 2.13 | `main.js` 全局注册，语言包 `zh-cn` |
| 图引擎 | AntV G6 4.8 | 拓扑编辑器使用自定义节点、边、动画和手动布局 |
| 路由 | vue-router 4 | `src/router/index.js` 集中声明路由 |
| HTTP | axios | `src/api/client.js` 集中封装 API |
| 状态 | Vue reactive | `state/auth.js`、`state/theme.js` |
| 主题 | Element Plus CSS 变量 | `html.dark` 驱动暗色模式 |

当前全局路由守卫处于临时强制放行状态：

```js
router.beforeEach((to, from, next) => {
  next();
});
```

后续恢复生产鉴权时，需要重新启用 `ensureAuthReady()`、`to.meta.public`、`to.meta.roles` 逻辑。

### 3.2 Backend

| 类别 | 技术 | 当前约定 |
| --- | --- | --- |
| Web 框架 | FastAPI 0.109 | `app/main.py` 注册所有 router |
| ORM | SQLAlchemy 2.0 | 模型集中在 `app/models` |
| 数据库 | SQLite | 默认 `runtime/platform_v2.db` |
| Schema | Pydantic 2 | 资产部分使用 Pydantic，拓扑 CRUD 当前接收 dict payload |
| 启动迁移 | 自定义轻量迁移 | `init_database()` 调 `Base.metadata.create_all()` 和 `_run_sqlite_migrations()` |
| CAD 解析 | ezdxf | 用于 CAD 图纸文本/点位抽取 |
| 服务启动 | uvicorn | 后端 API 默认由 FastAPI 提供 |

### 3.3 代码规范与约束

1. 前端 API 调用必须优先走 `src/api/client.js`。
2. 拓扑编辑器提交的结构化字段必须由后端原样持久化并返回，避免刷新后状态丢失。
3. 资产中心只读取资产主表和通道/链路上下文，不应解析前端画布状态。
4. 拓扑节点坐标属于 `network_topology_node`，资产主表只同步状态、备注、区域等业务可见字段。
5. `NetworkTopologyEdge.vlan_id` 是当前最新新增结构化字段，不能再只写入 `notes`。
6. 对旧表新增字段通过 `_run_sqlite_migrations()` 做幂等补列。

拓扑位置更新时的联动规则：

| 输入 | 同步结果 |
| --- | --- |
| `review_status = field_verified` | `asset_device.device_status = verified` |
| `review_status = pending_field_review / needs_field_check / conflict` | `asset_device.device_status = pending_field_review` |
| `manual_note` | 追加到 `asset_device.notes`，带“拓扑编辑器同步”前缀 |
| `area_id` | 若存在合法区域，写入 `asset_device.area_id` |
| `area_name / area_display_name` | 自动创建或复用 `asset_area` 后写入 `asset_device.area_id` |
| 无区域但有 `floor / weak_current_room` | 推断为 `中央大道 / floor / weak_current_room` 并尝试同步区域 |

接口：

```

请求结构：

  "src_node_key": "switch:10.0.68.9",
  "dst_node_key": "switch:10.0.68.46",
  "source_ip": "10.0.68.9",
  "target_ip": "10.0.68.46",
  "edge_type": "manual_uplink",
  "src_port_label": "gi24",
  "dst_port_label": "uplink",
  "vlan": "2",
  "vlan_id": "2",
  "layer_path": "aggregation->access",
  "evidence_type": "field_verified",
  "confidence": 1.0,
  "review_status": "field_verified",
  "manual_note": "现场确认 2F 4#井到 5F 4#井上联"
}
```

后端持久化规则：

| 请求字段 | 落库字段 |
| --- | --- |
| `src_node_key` / `source_node_key` | `network_topology_edge.src_node_key` |
| `dst_node_key` / `target_node_key` | `network_topology_edge.dst_node_key` |
| `edge_type` | `network_topology_edge.edge_type` |
| `src_port_label` / `source_port_name` | `network_topology_edge.src_port_label` |
| `dst_port_label` / `target_port_name` | `network_topology_edge.dst_port_label` |
| `vlan_id` / `vlan` | `network_topology_edge.vlan_id` |
| `layer_path` | `network_topology_edge.layer_path` |
| `evidence_type` | `network_topology_edge.evidence_type` |
| `confidence` | `network_topology_edge.confidence` |
| `review_status` | `network_topology_edge.review_status` |
| `notes` | `network_topology_edge.notes` |
| `manual_note` | `network_topology_edge.manual_note` |

响应结构：

```json
{
  "ok": true,
  "edge_id": 123,
  "architecture": {
    "domain": {},
    "summary": {},
    "simplified": {},
    "nodes": [],
    "edges": []
  }
}
```

注意事项：

1. 若未传 `src_node_key` 但传了 `source_ip`，后端推导为 `switch:{source_ip}`。
2. 若未传 `dst_node_key` 但传了 `target_ip`，后端根据 `edge_type` 尝试推导 `camera:{target_ip}` 或 `switch:{target_ip}`。
3. 创建连线后，后端会同步更新目标节点的 `parent_node_key` 和 `parent_ip`。
4. 返回的 `architecture.edges[*]` 同时包含 `vlan_id` 和 `vlan`，用于兼容前端显示。

## 6. 模块勾连关系说明

### 6.1 拓扑模块

入口：

| 前端路径 | 文件 |
| --- | --- |
| `/topology` | `frontend/src/views/TopologyEditorView.vue` |
| 核心组件 | `frontend/src/components/topology/TopologyEditor.vue` |

数据来源：

1. `TopologyEditor.vue` 调用 `fetchCentralAvenueArchitecture()`。
2. 前端从响应中读取 `nodes` 和 `edges`。
3. 画布由 G6 渲染，节点/边包含核实状态、端口、VLAN、备注、置信度。
4. 用户拖拽节点时调用 `updateAssetPosition()`。
5. 用户创建/修改连线时调用 `createArchitectureEdge()`。
6. 后端返回完整 `architecture`，前端可直接刷新画布状态。

关键状态字段：

| 字段 | 用途 |
| --- | --- |
| `review_status` | 控制已核实、待核实、冲突等视觉状态 |
| `manual_note` | 右侧情报录入抽屉和资产备注同步 |
| `vlan` / `vlan_id` | 链路归属模块与蓝线特效依据 |
| `src_port_label` / `dst_port_label` | 链路标签、端口证据 |
| `confidence` | 推算可信度与冲突提示 |
| `position_source` | 区分系统布局、手动固化、待核实池 |

### 6.2 资产模块

入口：

| 前端路径 | 文件 |
| --- | --- |
| `/assets` | `frontend/src/views/AssetCenterView.vue` |

数据来源：

1. 资产中心通过 `fetchDevices()` 拉取 `asset_device`。
2. 左侧空间树通过区域 API 或本地树结构过滤。
3. 表格行点击后右侧详情面板展示设备基础信息、诊断状态和快照。
4. 拓扑编辑器的位置保存会同步更新 `asset_device.device_status` 与 `asset_device.notes`。

联动重点：

| 拓扑动作 | 资产中心效果 |
| --- | --- |
| 拖拽固化坐标 | 资产备注追加“拓扑编辑器同步” |
| 传入 `review_status = field_verified` | 资产状态变为 `verified` |
| 退回待核实资产池 | 拓扑节点状态变为 `pending_field_review` |
| 传入区域字段 | 资产 `area_id` 更新，资产中心区域过滤可感知 |

### 6.3 大数据探针与清洗模块

主要输入：

| 文件/表 | 说明 |
| --- | --- |
| `runtime/analysis/normalized_switch_facts.json` | 交换机级联表规范化结果 |
| `runtime/analysis/normalized_camera_facts.json` | CAD/点位/摄像头信息规范化结果 |
| `runtime/analysis/excel_compare_report.json` | Excel 对账与冲突分析 |
| `runtime/analysis/asset_lineage/refined_topology.json` | CAD 物理坐标与逻辑级联缝合后的拓扑 JSON |
| `switch_live_probe` | 交换机实采探针结果，包含 ARP/MAC/HTTP/Telnet 等 |
| `topology_link` | 资产级物理链路证据 |

核心服务：

| 服务 | 作用 |
| --- | --- |
| `network_architecture.py` | 读取规范化事实，构建中央大道拓扑域 |
| `switch_live_probe.py` | 批量探测交换机，输出缺口和 MAC 命中 |
| `integrations.py` | 数据接入、缺口分析、批量建议 |

数据融合规则：

1. 交换机级联表提供骨干结构，来源标记为 `excel_switch_cascade`。
2. CAD 和摄像头表提供物理点位、楼层、区域、CAD_ID。
3. 运行库 `asset_device` 提供设备资产、MAC、平台来源和健康状态。
4. `topology_link` 提供更接近设备级的物理链路证据。
5. 人工编辑结果通过 `NetworkTopologyNode` 和 `NetworkTopologyEdge` 覆盖系统推算，`review_status` 和 `manual_note` 保留人工痕迹。
6. `central_avenue_architecture_payload()` 每次拉取都会合并当前数据库里的人工修正，避免重建时覆盖现场核实结果。

## 7. 端到端数据流

### 7.1 拓扑大盘加载

```text
TopologyEditor.vue
  -> fetchCentralAvenueArchitecture()
  -> GET /api/topology/architecture/central-avenue
  -> topology.py
  -> central_avenue_architecture_payload(db)
  -> network_topology_node + network_topology_edge + runtime analysis facts
  -> nodes/edges/simplified/summary
  -> G6 canvas render
```

### 7.2 手动连线保存

```text
用户在 G6 画布创建连线
  -> createArchitectureEdge(payload)
  -> POST /api/topology/architecture/edges
  -> create_architecture_edge(db, payload)
  -> 写 network_topology_edge
  -> 写 dst.parent_node_key / dst.parent_ip
  -> 返回 edge_id + architecture
  -> 前端刷新光子流连线和链路标签
```

### 7.3 节点拖拽固化与资产中心同步

```text
用户拖拽节点
  -> updateAssetPosition(payload)
  -> POST /api/assets/update_pos
  -> _update_topology_node_position(db, payload)
  -> 写 network_topology_node.pos_x / pos_y / review_status / manual_note
  -> _sync_topology_node_to_asset()
  -> 写 asset_device.device_status / notes / area_id
  -> 资产中心 fetchDevices() 可直接看到新状态
```

### 7.4 探针到拓扑

```text
交换机实采探针
  -> switch_live_probe
  -> ARP/MAC/端口/VLAN/可达性结果
  -> topology_link 或分析报告
  -> network_architecture.py 重建或合并
  -> network_topology_node / network_topology_edge
  -> TopologyEditor.vue 统一展示
```

## 8. 状态枚举建议

### 8.1 review_status

| 值 | 含义 |
| --- | --- |
| `system_built` | 系统根据清洗脚本或级联表构建 |
| `needs_field_check` | 需要现场核实 |
| `pending_field_review` | 待现场核实，常用于待命资产池 |
| `field_verified` | 现场已核实 |
| `conflict` / `conflicted` | 存在冲突，需人工处理 |

### 8.2 evidence_type

| 值 | 含义 |
| --- | --- |
| `excel_switch_cascade` | 来自交换机级联表 |
| `manual_result` | 人工新增或编辑 |
| `manual_override` | 人工覆盖已有系统结果 |
| `field_verified` | 现场核实 |
| `direct_switch_mac_probe` | 交换机 MAC 表实采命中 |
| `platform_terminal_fact` | 平台终端关系推断 |

### 8.3 position_source

| 值 | 含义 |
| --- | --- |
| 空字符串 | 未固化坐标 |
| `manual` | 用户手动拖拽固化 |
| `orphan_pool` | 已退回待核实资产池 |
| `field_verified` | 节点创建或更新时带现场核实坐标 |

## 9. 开发对接清单

### 9.1 新增拓扑字段时

1. 先修改 `backend/app/models/asset.py` 中的 ORM 模型。
2. 在 `backend/app/core/database.py` 的 `_run_sqlite_migrations()` 中添加幂等补列。
3. 在 `network_architecture.py` 的创建、合并、返回函数中加入字段。
4. 在 `frontend/src/api/client.js` 保持原 payload 透传。
5. 在 `TopologyEditor.vue` 中只消费结构化字段，避免从 `notes` 里解析关键状态。

### 9.2 修改资产状态时

1. 优先更新 `asset_device.device_status`。
2. 健康状态使用 `health_state`，不要和 `device_status` 混用。
3. 现场核实痕迹追加到 `asset_device.notes`，不要覆盖原始导入说明。
4. 区域变化通过 `area_id` 表达，必要时用 `_get_or_create_area_by_name()` 创建区域。

### 9.3 恢复生产鉴权时

1. 恢复 `router.beforeEach` 中的 `ensureAuthReady()`。
2. 保留 `/login` 的 public meta。
3. 检查 `/topology` 是否需要 `roles: ["admin", "manager"]`。
4. 后端目前 `POST /topology/architecture/edges`、`POST /assets/update_pos` 已要求 `admin` 或 `manager`。
