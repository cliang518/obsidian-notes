# 00_系统架构与开发规范 (V1.0 基础版)

## 1. 唯一工程入口与 AI 视界隔离
- **核心原则**：本项目全面拥抱 Vue 3 (Composition API + `<script setup>`)。
- **物理隔离指令 (最高优先级)**：作为 AI 助手，你的“视界”被严格限制在 `E:\cctv-maintenance\platform_v2\` 目录下。**绝对禁止**你读取、分析、修改根目录 (`E:\cctv-maintenance\`) 下的任何其他旧文件（如旧版的 index.html、旧 backend、旧 data 目录）。假装它们不存在！
- **工作区**：所有的前端开发工作仅限在 `platform_v2/frontend/src` 目录下进行。

## 2. 目录职责划分 (严格遵守)
在 `src` 目录下，所有文件必须严格归类，禁止平铺：
- `/api`: 存放所有 Axios 请求封装。组件内禁止直接写 `axios.get`。
- `/components`: 存放“纯粹的”UI 零件。这里的组件只负责接收 `props` 并渲染，**禁止在组件内直接发网络请求或生成 Mock 数据**。
- `/views`: 存放路由页面组件。页面组件负责调用 `/api` 获取数据，然后把数据喂给 `/components`。
- `/store`: (待建) 存放全局状态（如 WebSocket 推送的实时告警数据）。
- `/utils`: 存放纯函数工具（如日期格式化、数据清洗）。

## 3. 拓扑图开发铁律 (针对 CyberTopologyGraph)
- **UI 唯一性**：绝对禁止在同一个组件内，既用 DOM (HTML div) 渲染设备卡片，又用 G6 (Canvas) 渲染图表！必须二选一。我们统一采用 **G6 Canvas 内部渲染降维状态卡片** 的方案，绝不能把几百个摄像头作为独立节点渲染到全局画布中。
- **数据剥离**：拓扑图组件只接受一个干净的 `graphData` Prop。那些把不同来源数据糅合在一起的逻辑（如 `collectSwitchSources`），必须抽离到 `utils` 或外层的 View 组件中处理。
- **状态流转**：禁止在拓扑组件内写 `setInterval` 生成假数据。实时状态必须由外层传入，组件只负责暴露一个 `updateNodeStatus(nodeId, status)` 的靶向更新方法供外部调用。

## 4. UI 体系构建
- 本项目严禁大面积手写基础 UI 样式的 CSS。
- 所有的基础交互组件（按钮、弹窗、抽屉、表格），后续将统一引入成熟的 Vue 3 组件库（如 Element Plus 或 Ant Design Vue）进行构建，以确保工业级后台的视觉严谨性。
